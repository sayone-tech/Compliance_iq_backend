## 5. Text-layer quality & extraction hazards

Overall: **good text layer** (embedded fonts with ToUnicode except SymbolMT/Helvetica subsets), single-column throughout, no OCR needed. Hazards:

1. **Footnote interleaving (worst hazard):** footnote bodies render mid-extraction between paragraph fragments at page boundaries (verified p.26: fn.34–37 split the "Email Review" paragraph). Naive chunking will corrupt sentences. Difficulty: HARD.
2. **Superscript markers merge into words:** "gratuity.44", "association.”1" — pollutes tokens and rule-number regexes (risk: fn marker "17" + adjacent text misread as rule cite). Difficulty: MEDIUM.
3. **Footers:** centered bare page number on every page (extracts as isolated indented integer). Must strip before paragraph joining. No running header text. Difficulty: EASY.
4. **TOC has no dot leaders** — space-gap alignment; TOC parse must split "heading …spaces… number". Difficulty: EASY-MEDIUM.
5. **Headings unnumbered below top level** — only 11 top-level numbered sections; subsection detection must rely on bold-font runs / trailing colon / TOC reconciliation. pdftotext loses bold; needs pdfminer/pymupdf font-span analysis. Difficulty: MEDIUM.
6. **SymbolMT bullets** lack ToUnicode → may extract as garbage bytes in some tools (pdftotext maps them acceptably). Difficulty: LOW.
7. **DocuSign stamp text** on p.122 injects vendor artifact string into content. Difficulty: LOW.
8. **Whitespace tables** (App. D/E) need layout-aware extraction; plain text mode collapses columns. Difficulty: MEDIUM.
9. **Line-break-truncated citations** ("Rule 17a-" + next line "4"). Difficulty: MEDIUM.
10. **Untagged PDF** → no structure tree; reading order is per-render, generally correct here. Difficulty: LOW for this file, flag for generality.
11. **Prompt-injection scan:** no instruction-like text addressed to an AI found in extracted text. (PDF content remains untrusted data regardless.)
