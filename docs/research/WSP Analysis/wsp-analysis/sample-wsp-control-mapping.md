# Sample WSP Control Mapping — Proof of Concept (Brief Section 39)

**Date:** 2026-08-17 · **Status:** Research/architecture only.
**WSP1** = `Sample WSP.pdf` (WealthForge Securities, LLC, 154 pp, 2024) · **WSP2** = `WSP Sample.pdf` (Triad Securities Corp., 199 pp, 2013).
Controls are drawn verbatim from the platform's regulatory control libraries: `../regulatory/wsp-mica-analysis.md` (MICA-WSP-001…024) and `../regulatory/wsp-dora-analysis.md` (DORA-WSP-001…015). Authority hierarchy: **Official Regulation → Requirement → Control → Expected Evidence → WSP evidence.** The two sample WSPs sit at the *bottom* of that chain — they are test inputs, never authority.

---

## 1. How to read this table

Both samples are **US FINRA broker-dealer manuals containing zero EU instruments** (verified: `notes-sample-wsp-1.md` §9, `notes-sample-wsp-2.md` §7). Therefore no cell below can ever be "COMPLIANT". Evidence-status vocabulary:

- **ANALOG** — the manual documents a functionally similar policy under US rules; a MiCA/DORA-specific adequacy judgment would still fail on EU-specific elements. **REQUIRES LEGAL / COMPLIANCE INTERPRETATION** in every case.
- **PARTIAL** — some expected elements present, named gaps identified.
- **MISSING** — no relevant evidence anywhere in the document. *This is the product's value demonstration:* the engine must find, cite, and grade absences, not just presences.

DORA rows are additionally **evidence-gap findings only, never breach determinations** (per `wsp-dora-analysis.md` §1: the required policy may live in a document other than the WSP). Neither sample firm is a DORA/MiCA-scoped entity at all — the mapping simulates what the engine would output *if* an EU CASP uploaded a manual with this content.

## 3. What this table demonstrates (product value)

1. **The MISSING column is the product.** WSP2 yields a near-total DORA gap profile (rows 2, 11–15) — a validator that only matches present text would return nothing; this engine returns 6+ severity-graded absence findings with control citations.
2. **PARTIAL findings carry named sub-gaps** (row 13: "BCP exists but states no RTO/RPO and no test schedule") — exactly the evidence-backed granularity the PRD requires. Sub-gap tokens (RTO, RPO, "72 hours", template fields) are deterministic checks layered under a semantic adequacy judgment.
3. **ANALOG ≠ compliant.** Rows 3, 8, 10 would fool a keyword system ("records", "suitability", "AML" all present). The engine must judge against the EU control's specific elements (5-yr retention wording, 12-month periodic statement, travel-rule data fields) and still flag EU-specific gaps. Every ANALOG verdict is **REQUIRES LEGAL / COMPLIANCE INTERPRETATION**.
4. **Applicability gating matters:** rows 8–9 apply only to certain CASP service types (advice/PM; PPAETs), and DORA rows are suppressed/downgraded for Art. 3(60) microenterprises — firm metadata (authorised services, authorisation status, size) is an input to the mapping, not an afterthought.
5. **Evidence anchoring worked at page/section granularity** for every non-MISSING cell using the parity property (printed page = PDF page in both samples) — validating the `(doc, section, page)` citation contract.
